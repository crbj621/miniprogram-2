# 业务与算法规则

规则以服务端实现为准；前端隐藏不是权限验证的替代。

## 身份、模块与管理

- 学生身份以服务器 token 与 App 登录状态为准。保存资料成功后才提交登录；authVersion/sessionVersion 防止退出前请求回写。
- 五个模块键：running、canteen、forum、english、gifts。已发布旧版公开接口仍收到固定false的food/rider字段以隐藏旧入口，后台不列出且不能重新开启。服务端兼容旧布尔值和 run 键，规范写入 `{ enabled, name }`，部分更新不清空其他设置。
- 同学端读取公开模块配置，区分加载、失败、全部关闭。关闭模块隐藏入口和相关菜单；食堂服务端同步拒绝学生访问。
- 超级管理员且账号未禁用才可改开关；读取失败不能保存。快捷设置需点击保存才生效。
- 管理首页常用入口是模块、食堂、跑步、公告；其他事务折叠。管理权限仍由服务器验证。

## 跑步、组队与榜单

- GPS 距离结合精度、速度、时间、计步过滤静止抖动、跳点和折返噪声；保留有计步支持的真实转弯。新增传感器步数只用于显示，不直接折算距离，解绑使用同一回调。
- 开始自动收起卡片；暂停展开；继续收起。运动中准备功能与底部导航隐藏，暂停 / 结束在卡片外保留。
- 失败或离线成绩存当前用户本机队列，用相同 clientRunId 重试，服务器成功后才清除。零距离不写假成绩；队伍结算必须等待成绩保存。
- 排名先完整汇总再取榜单前列，不能先截断 1000 条。相同里程保持稳定顺序，追赶距离不伪造。
- “搭子和情侣”榜沿用 couple 类型，只累计同一对成员关联队伍下的已保存成绩；普通多人队伍不混入。
- 组队资格、完成判定和成绩保存使用服务端校验、事务及数据库锁。示例成绩由管理员明确生成，可从跑步管理移除；不能删除真实记录来保持空库。

## 独立食堂评价与投稿

- packageCanteen / canteen_reviews 使用独立集合；点餐功能已移除。档口、菜品、评论、独立评分分别为 canteen_stalls、canteen_dishes、canteen_reviews、canteen_ratings；完整接口和维护关系见 [食堂模块](canteen.md)。
- 同一学生可多次评论，同一道菜只计其最新的1–5分评分；纯交流不改评分。评论与评分分开存储，删除本人评论仍保留最新评分。旧评论第一次读取时幂等迁入独立评分，不删除原记录。
- 至少两票且均分 ≥ 4 为推荐，至少两票且均分 ≤ 2.5 为避雷。无评价显示暂无评分。
- 优质随机先筛 ≥ 4 分且两票；全部随机抽已发布菜品；异食癖随机先筛 ≤ 2.5 分且两票。使用 crypto.randomInt 等概率抽候选，无候选显示空池。
- 菜品按实际均分、评分人数和名称稳定排序；档口汇总其菜品的有效评分，所以档口显示“份评分”，不是不同学生数。只计算visible评分，不以评论数量或点赞数改变均分。
- 每人对每条评论只能选“有用”或“存疑”之一，同项再点取消，作者不能给自己反馈。至少5位不同学生存疑且占反馈≥70%时标记争议；只有该评论关联当前最新评分时才自动暂停该评分。纯交流和旧评分评论不会暂停另一个最新评分。
- 达到门槛后由管理员恢复或排除；反馈比例下降不自动恢复。核查期间允许继续交流，禁止改分绕过暂停；管理员恢复评分不会恢复已删除的评论。隐藏评论只排除它所关联的当前评分，作者不能重发同请求恢复隐藏或已删除记录。
- 新投稿可为档口、菜品或已有档口补图，同事务自动发布，不自动加评分。clientId防重复请求；同档口名＋位置及同档口下菜名进行NFKC、空白与大小写规范化后检查，并发写入使用现有MariaDB业务锁。相近名称仅提示候选，不擅自合并不同窗口。
- 同学可给已有档口补图；第一张档口实拍自动填空封面，已有封面由管理员选择。菜品图片不会误设为档口封面。本人可修改投稿；原菜品投稿人修改名称、价格、说明、供应时间和图片时保留原菜品ID及评分。其他贡献者只能修改自己的投稿信息。
- 本人撤回投稿后，自己的文字与图片引用移除；存在其他贡献、评论或评分的共享档口／菜品继续保留。无人参与且来源全部撤回的实体收起，不删除别人的内容。此操作没有新增食堂上传文件的磁盘孤儿清理，不能当作物理文件已删除。
- 早餐、午餐、晚餐按菜品供应时间筛选；默认投稿“午餐＋晚餐”，共用同一菜品和评分。旧菜品无餐次字段按全天兼容；随机抽取也遵循当前餐次。
- 至少3位不同用户举报后交管理员核对，重复举报不累计，不自动隐藏；举报与“存疑暂停评分”是不同处理流程。历史pending投稿仍由管理端“旧投稿”处理一次。草稿不对同学显示，所有修改在服务器验证本人／管理员及模块权限。

## 校园动态

完整分区来自 forum 接口；栏下菜单选择后收起，新分区复位第一页。最新 / 热门与分页使用请求序号，旧响应不能覆盖新筛选；失败不跳过页码。私信与未读信息要求学生身份。

## 验证边界

当前25组本机回归覆盖英语学习与整卷交卷、媒体、登录、模块、评分、事务请求、跑步交互／漂移、刷新竞态、榜单、每日主题、网站与分享。服务器真实HTTP/SQL与专项脚本在server/scripts，运行前考虑真实用户；脚本会创建临时数据，部分会暂时改模块设置，应使用测试库或维护窗口。

已有接口与数据库回归不能证明真实微信登录、手机弱 GPS / 锁屏、照片上传或配送全流程完成，也不是完整安全审计。

## 校园跑当前实现（2026-10-04）

本节描述已实现的代码；当前服务端发布点为 `20261004-040854`，微信端已生成新版官方预览，尚未正式发布。

### 根因与改造

旧实现按 accuracy 乘位移，导致同一约 20 米路段在 accuracy=65 时只记 10 米；距离又被反算成步数。结束弹框使用早先捕获的距离，活动状态只保存在内存，补传日期取收到当天。服务端接受零时长或极端速度，榜单先载入整个集合。

| 当前规则 | 源码 |
| --- | --- |
| 球面距离保留，不按精度给米数打折；accuracy >80、非法坐标、超过 15 秒采样间隔断段，不跨缺口补直线 | utils/run-metrics.ts、pages/index/index.ts |
| speed ≤0.6时不计距，传感器峰值不能绕过；连续位移超过12 m/s或单段超过180米拒绝。孤立跳点回漂撤销上一段，不能只因手机加速度峰值就保留噪声 | RunTracker |
| 精度决定准入和微小位移门限（4–12米），未知速度还需连续同向样本确认，不是距离折扣；未提供速度的设备不能因此宣称完全排除静止漂移 | RunTracker |

### 开源调研与选型

检索关键词：`GPS running accuracy JavaScript geolib`、`Kalman filter GPS JavaScript`、`Turf distance simplify`、`wechat-miniprogram getWeRunData`、`MariaDB generated virtual columns JSON index`。

- [geolib](https://github.com/manuelbieh/geolib)：地理距离函数候选；现有公式不是偏差根因，因此不额外引入。
- [KalmanJS](https://github.com/wouterbulten/kalmanjs)：一维噪声滤波参考，不能直接作为完整 GPS / 惯性融合；本次未引入，避免未经真实轨迹标定就削短弯道。
- [Turf](https://github.com/Turfjs/turf)：轨迹简化 / 地理围栏候选；本次仅限制绘图点数，不将简化轨迹用于计距。
- [微信官方示例](https://github.com/wechat-miniprogram/miniprogram-demo)与 [API 定义](https://github.com/wechat-miniprogram/api-typings)：登录、定位和微信运动接口依据。
- [MariaDB 虚拟列与索引](https://mariadb.com/docs/server/reference/sql-statements/data-definition/create/generated-columns)：沿用现有 MariaDB + mysql2 聚合，无新 ORM。

本次没有新增依赖；没有找到直接匹配且已核对的 SkillHub 技能，未安装社区脚本。

### 微信运动（日步数独立功能）

校园跑准备卡片新增“今日微信运动”。用户主动点击同步并允许 scope.werun 后，客户端刷新 wx.login，获得同一微信会话的 encryptedData/iv，提交 `/api/we-run`。服务端用 Node.js 自带 crypto 解密，核对用户、AppID、水印时间（15 分钟内）、日日期、重复日与非负整数步数，按用户与日期更新 `wechat_steps`。

JWT 只关联一个微信会话 ID；session_key 仅在服务器内存中保存 2 小时，重启后点击同步会重新登录，不返回给客户端、不写日志。不同设备 / 登录对应不同会话，避免互相覆盖。旧水印请求不能覆盖较新步数。维护目录的账号密钥仍按用户要求保存明文，微信接口数据解密与维护文件存储方式无关。

官方目前提供过去三十一天的按日数据，用户主动授权后，进入跑步页、开始／结束运动时在前台自动同步，60秒防重；本项目旧类型注释写三十天，以最新官方定义为准。今日无数据显示横线，不用昨天数据冒充。最近 31 日可返回接口，界面当前只显示今日与同步时间，没有额外新增日步数榜。

微信日步数包含当天其他活动，不能可靠地作为一次跑步的实时步数、配速、步频、精确补距或防作弊证据；不混入跑步统计、榜单或组队完成判定。

## 祝福网站、分享与食堂举报（2026-10-04）

网站先免费实时预览，编辑中续期、离开2分钟回收；首次正式网站2小时全特效免费，标准3天／7天／15天／1个月，背景和特效按选择收费，最多同时3站。公示默认关闭，正式有效且开启公示的网站才进入下方广场；任何模板支持署名或匿名留言。价格、画布、清理与超级管理员发金币事务见[gift-sites.md](gift-sites.md)。所有页面有好友／朋友圈分享；私人页面只分享公开入口，不发送答题记录、订单、聊天或管理参数。

食堂新投稿自动公开，按同用户clientId防重；档口和菜品编号使用64位哈希，符合数据库document_id长度。至少3位不同用户举报才进入管理员核对队列，重复举报不累计，不自动隐藏。核实无误／下架由管理员完成，已处理计数从新的独立举报继续累计。旧待审投稿保留在管理端“旧投稿”，不自动改动历史内容。

静止GPS速度不超过0.6m/s时不计距，传感器峰值不能绕过静止或跳点筛选；未知速度采用连续方向与时间确认，防止甩手机产生短跳点。微信运动是当日总步数，不适合作为本次实时跑步距离补偿。真实室内外、慢速跑、转弯与后台轨迹仍需手机标定。
